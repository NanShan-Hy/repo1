# 云端值守中心（GitHub Pages 24小时在线服务方案）

## 项目简介
- 本项目将原有零散文件重构为可直接部署到 **GitHub Pages** 的静态网站，实现“以 GitHub 即服务器”的全天候展示方案。
- 页面围绕“24 小时可用”的运维主题构建，提供实时状态、运维节奏、部署指引、支援中心与知识库等模块，便于快速推广企业官网或服务大厅。
- 所有代码均配有逐行中文注释，帮助团队成员迅速理解逻辑并进行二次开发。

## 目录结构
```
├── README.md                 # 中文说明文档与部署指南
├── index.html                # 网站入口页面，可作为 GitHub Pages 根目录
└── assets
    ├── css
    │   └── style.css         # 全站样式，内含主题切换与响应式布局
    └── js
        └── main.js           # 功能脚本，包含状态刷新、支援记录等逻辑
```

## 核心功能
1. **运行总览看板**：动态展示可用率、巡检倒计时、自动化脚本状态，模拟 24/7 运维节奏。
2. **运维节奏时间线**：用数据驱动的方式说明全天不同时间段的自动化任务安排。
3. **GitHub Pages 部署指南**：页面内置三步部署流程，新手也可快速上线。
4. **在线支援中心**：表单提交信息会保存在浏览器 LocalStorage，并同步到“运维看板”浮动面板，方便追踪。
5. **知识库精选**：精选 GitHub Actions、Pages、Cloudflare 等官方中文文档，帮助持续优化。
6. **主题切换**：提供浅色/深色主题，满足不同环境的展示需求。

## 部署到 GitHub Pages
1. **Fork 或克隆仓库**：`git clone` 到本地，根据业务需求调整页面内容与样式。
2. **推送到 main 分支**：确保 `index.html` 位于仓库根目录，资源文件存放于 `assets/`。
3. **启用 Pages**：进入仓库 `Settings` → `Pages`，选择 `main` 分支与根目录作为发布源，保存后即可获得公开访问地址。
4. **绑定自定义域名（可选）**：在 `Pages` 设置中填写域名，并在域名服务商处添加 CNAME 与 A 记录，即可实现企业级访问体验。

## 持续可用性建议
- **自动构建**：结合 GitHub Actions 定期（如每日）构建，自动化发布最新内容。
- **外部监控**：可选用 UptimeRobot、BetterStack 等监控服务，对 Pages 站点进行 HTTP 心跳检测。
- **缓存与加速**：搭配 Cloudflare、Fastly 等 CDN，可在全球范围获得更好的访问速度与安全防护。
- **数据备份**：支援记录存储于浏览器端，如需团队共享，可接入 Serverless 或第三方表单服务。

## 本地预览
1. 安装任意静态服务器（如 `npm install -g serve`）。
2. 在仓库根目录执行 `serve .` 或使用 VS Code Live Server 插件。
3. 浏览器访问 `http://localhost:3000`（端口随工具而定）即可预览效果。

## 自定义与拓展
- **内容替换**：直接编辑 `index.html` 的模块文案，所有元素均配有中文注释，定位快速。
- **样式调整**：`style.css` 提供大量 CSS 变量，可在 `:root` 中一次性调整颜色、阴影等视觉元素。
- **功能扩展**：在 `main.js` 中追加新的运维任务、支援记录处理逻辑或第三方 API 调用即可扩展功能。
